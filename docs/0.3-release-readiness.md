# Tracelet 0.3 release readiness

Last reviewed: 2026-10-23

This checklist defines the evidence required before `tracelet-browser@0.3.0`
can move from beta to the npm `latest` tag. A checked item must link to an
automated gate or an inspectable artifact; release intent alone is not enough.

## Public API and package

- [x] The observability API is accepted and frozen in
  [`rfcs/0001-observability-api.md`](./rfcs/0001-observability-api.md).
- [x] The ESM-only distribution scope is accepted in
  [`rfcs/0002-distribution-formats.md`](./rfcs/0002-distribution-formats.md).
- [x] The public runtime export snapshot covers all 26 exports.
- [x] The installed tarball resolves at runtime and through TypeScript.
- [x] The package budget enforces compressed size, unpacked size, file count and
  the allowed-file boundary.
- [x] React/Vite, Vue/Vite, Next.js/Turbopack, Webpack and Rollup install and
  build the current tarball in CI.

## Browser reliability and privacy

- [x] Chromium, Firefox and WebKit deliver through the real local collector.
- [x] IndexedDB survives reloads and `createBrowserEventStorage()` verifies
  persistent selection in all three browser engines.
- [x] Offline-to-online recovery retains and later delivers the same event.
- [x] `pagehide` and hidden-page `visibilitychange` flushes are isolated tests.
- [x] Two real tabs coordinate one shared IndexedDB queue without duplicate IDs.
- [x] CSP `connect-src 'none'` prevents delivery without deleting the event.
- [x] Consent denial prevents identity creation and persistence.
- [x] URL query strings and fragments are excluded from default page context.

The complete support boundary and intentionally partial environments remain in
[`compatibility-matrix.md`](./compatibility-matrix.md). A documented partial row
does not block 0.3 unless the README claims that environment as supported.

## Collector and operations

- [x] JSON and gzip batches share one validated protocol contract.
- [x] Origin allowlisting, optional authentication and compressed/decoded body
  limits are covered by collector contract tests.
- [x] Retry attempts expose correlation IDs, status, schedule and immutable queue
  snapshots without payload or identity data.
- [x] The durable Sink contract requires database-level `eventId` idempotency;
  Tracelet does not claim exactly-once delivery without it.

## Documentation and project health

- [x] Quickstart, object guide, examples and API Reference cover the current
  production storage, transport, consent and diagnostics paths.
- [x] Security, support, contribution and release policies are present.
- [x] The documentation website has SEO/GEO output checks and JavaScript budgets.
- [x] There are no open public GitHub Issues as of the review date.

## Release execution

- [x] Change `package.json` and generated version metadata to `0.3.0-rc.1`.
- [x] Pass the complete CI suite on the exact RC commit ([run 39921645267](https://github.com/shishikami/Tracelet/actions/runs/39921645267)).
- [ ] Publish and approve the RC with the npm `beta` dist-tag.
- [ ] Install the public RC into a clean project and verify runtime, declarations
  and one real collector delivery.
- [ ] Promote the same accepted API to `0.3.0`, pass CI, publish the GitHub
  Release and approve npm staged publishing with the `latest` dist-tag.
- [ ] Verify `npm view tracelet-browser@latest version` returns `0.3.0` while the
  release page, package provenance and documentation all reference the same tag.

The unchecked items are release operations, not hidden implementation work.
They must be completed in order and must not be bypassed after a failed gate.
