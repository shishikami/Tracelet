01 · Overview

核心设计

SDK Core 只定义事件生命周期和抽象接口。任何后端差异都收敛在 Adapter 边界，避免扩散到业务代码。

◇

类型安全事件

通过 TypeScript EventMap 在编译期检查事件名、必填字段与属性类型。

↻

可靠投递

批量发送、IndexedDB 持久化、页面退出 Flush，以及带抖动的指数退避。

⊙

隐私优先

Consent 在事件创建前拦截；撤回授权可同时清空队列和本地身份。

⬡

完全可插拔

Plugin、Codec、Compression、Storage 和 Transport 都有独立契约。

边界原则业务依赖 SDK API，SDK Core 依赖抽象接口，Adapter 才依赖具体平台。
02 · Installation

安装与构建

当前仓库是零运行时依赖的 TypeScript 包。安装开发依赖并构建：

pnpm install
pnpm build
pnpm test

构建产物输出到 dist/，入口为 dist/index.js。应用内可直接从包入口导入：

import {
  createAnalytics,
  HttpTransport,
  IndexedDbEventStorage,
  BrowserLocalStorage,
} from "@et/analytics-sdk";
03 · Quickstart

五分钟接入

1

定义业务事件

事件类型只存在于应用侧，不会让 Core 与业务 Schema 强耦合。

interface AppEvents {
  product_viewed: {
    productId: string;
    category?: string;
  };
  order_submitted: {
    orderId: string;
    amount: number;
    currency: "CNY" | "USD";
  };
}
2

创建 SDK 实例

浏览器生产环境建议显式使用 IndexedDB 与 localStorage。

const analytics = createAnalytics<AppEvents>({
  appId: "commerce-web",
  appVersion: "1.0.0",
  environment: "production",
  identityStorage: new BrowserLocalStorage(),
  eventStorage: new IndexedDbEventStorage(),
  transport: new HttpTransport({
    endpoint: "https://events.example.com/v1/batch",
  }),
  retry: {
    baseDelayMs: 1_000,
    maxDelayMs: 60_000,
    jitterRatio: 0.2,
  },
});

await analytics.init();
3

发送业务事件

await analytics.track("order_submitted", {
  orderId: "o_123",
  amount: 199,
  currency: "CNY",
});
04 · Collection

事件 API

track(name, properties, options?)Promise<void>

记录一个类型安全的业务事件。可用 options.timestamp 覆盖发生时间。

page(name, properties?)Promise<void>

记录页面访问，SDK 自动补充 URL、路径、标题与 Referrer。

identify(userId, traits?)Promise<void>

绑定登录用户，并发送 $identify 事件。

flush(reason?)Promise<void>

立即发送当前批次。同一时间只允许一个 Flush 执行。

reset()void

退出登录时清除 userId，并生成新的 anonymousId 与 sessionId。

shutdown()Promise<void>

停止定时器、解绑页面事件、完成最后一次发送并销毁插件。

05 · Identity

身份与会话

每个事件都携带三层身份。服务端可以按 eventId 去重，并按身份字段完成后续合并。

字段来源用途
anonymousId首次访问生成登录前行为串联
userIdidentify()跨设备登录身份
sessionId会话生成一次访问范围
eventId每个事件生成服务端幂等去重
注意当前 starter 尚未实现空闲超时自动续期。可调用 IdentityManager 的 renewSession()，或在后续阶段增加 Session 策略。
06 · Privacy

Consent 管理

Consent 检查发生在创建事件和生成身份之前。需要用户授权的项目应从 pending 开始。

const analytics = createAnalytics({
  appId: "shop-web",
  transport,
  consent: {
    initialState: "pending",
    clearQueueOnDenied: true,
  },
});

await analytics.setConsent("granted"); // 开始采集
await analytics.setConsent("denied");  // 清队列、清身份
pending

等待用户决定，不创建事件。

granted

允许采集、排队和投递。

denied

阻断采集，可清理已有数据。

07 · Plugins

插件管线

插件在编码前处理标准 JavaScript 事件。返回 null 会丢弃事件；诊断能力可以观察这一行为。

const analytics = createAnalytics({
  appId: "shop-web",
  transport,
  plugins: [
    redactPlugin(["password", "token", "authorization"]),
    samplingPlugin({ mouse_moved: 0.01 }),
  ],
});
setup→beforeTrack→Queue→afterTrack→teardown
08 · Storage

持久化队列

SDK 提供统一的 EventStorage 契约。开发和测试可用内存队列，浏览器生产环境推荐 IndexedDB。

MemoryEventStorage

  • 零配置、速度快
  • 刷新页面即丢失
  • 适合测试和 SSR
Recommended

IndexedDbEventStorage

  • 未发送事件跨刷新保留
  • FIFO 读取
  • 适合失败重试
eventStorage: new IndexedDbEventStorage({
  databaseName: "commerce-analytics",
  storeName: "events",
})
09 · Delivery

批量与重试

01

进入队列

事件先持久化，再判断是否达到批量阈值。

02

触发 Flush

定时、队列满、手动或页面隐藏均可触发。

03

发送结果

成功出队；408、429、5xx 或网络失败进入退避。

04

幂等去重

服务端依据稳定 eventId 去重。

投递语义浏览器无法保证严格 exactly-once。推荐“客户端至少一次投递 + 服务端 eventId 幂等”。
10 · Encoding

Codec 与 Protobuf

编码位于插件和批量之后、Transport 之前。Core 内置 JSON，并允许注入任意 Protobuf 生成器。

const codec = new ProtobufCodec((batch) => {
  return EventBatch.encode(
    EventBatch.fromJSON(batch),
  ).finish();
});

const analytics = createAnalytics({
  appId: "shop-web",
  codec,
  compression: new GzipCompression(),
  transport,
});

建议先优化批量、字段和采样，再评估 Protobuf。压缩后的 JSON 与 Protobuf 差距通常小于未压缩数据。

11 · Transport

Transport

Transport 只接收已经编码和压缩的 Batch，并把不同后端响应归一化成统一结果。

interface TransportResult {
  success: boolean;
  retryable?: boolean;
  status?: number;
  retryAfterMs?: number;
}
响应默认行为
2xx成功，批次出队
408 / 429 / 5xx保留批次并指数退避
其他 4xx不可重试，移出队列
网络错误保留批次并重试
12 · Observability

诊断事件

onDiagnostic 不创建业务事件，不会导致递归采集，适合接入日志或前端监控。

const analytics = createAnalytics({
  appId: "shop-web",
  transport,
  onDiagnostic(event) {
    console.debug("[analytics]", event);
  },
});
sdk_initializedevent_enqueuedevent_droppedflush_startedflush_succeededflush_failedflush_retry_scheduledsdk_shutdown
13 · Collector

服务端协议

SDK 默认向 Collector 发送一个带协议版本和发送时间的事件批次。

{
  "protocolVersion": "1",
  "sentAt": "2026-10-16T08:00:00.000Z",
  "events": [
    {
      "eventId": "…",
      "type": "track",
      "name": "order_submitted",
      "timestamp": "…",
      "identity": { "anonymousId": "…", "sessionId": "…" },
      "properties": { "orderId": "o_123", "amount": 199 },
      "schemaVersion": "1"
    }
  ]
}
方法路径用途
POST/v1/batch接收 SDK 批量事件
GET/v1/events本地查询最近事件
GET/v1/stats查看批次、失败与请求日志
POST/v1/control/failure本地注入响应故障
